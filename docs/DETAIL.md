# 绝区零 · 立绘挂件

把《绝区零》预约活动页里的元素搬到 DSH 界面上：输入框右上角站着「柔光之影」，运行中的「深度求索中」前面转着一朵小黄花。

## 功能

- **输入框右上角的立绘**：只保留活动卡片的首位角色「柔光之影」，循环播放 `idle` 待机动作，悬停时轻微上浮。点击角色让它变透明（约 12% 不透明度），用来查看被立绘盖住的对话内容与控件；再点一次恢复。角色身上不出任何文字：没有悬停提示框，也没有常驻角标——提示框正好盖住用户想看的那块；状态只保留在 `aria-label` / `aria-pressed` 里供读屏使用。
- **层级**：立绘挂在输入框卡片的 overlay 槽位里。排队消息条在页面顺序上位于输入框之前，而立绘是绝对定位，会盖住排队消息条的展开箭头与编辑/删除/插话按钮并吞掉点击；插件因此把 `[data-queue-dock]` 抬到立绘之上（`position: relative; z-index: 2`）。命令菜单等卡片内的浮层自带更高的 z-index，仍显示在最上层。
- **出现在所有会话**：挂件挂在输入框卡片的 overlay 槽位，因此每个会话（包括新建会话的空白页）的输入框右上角都能看到角色。空白页本身保持 DSH 原样，不再铺背景。
- **运行中的小黄花**：会话跑起来时，Chat 会在轮次末尾显示「深度求索中，用时 …」；插件把它前面那只鲸鱼尾巴换成活动页里旋转的小黄花。花朵取 `levels_hua` Spine 的 `a1` 帧，只还原了其中的旋转：`rotateSpeed = -0.3`，即顺时针 3.33 秒一圈（原引擎还叠了 x 方向摆动与缩放脉冲，在图标尺寸下只会读成抖动，所以没有搬）。鲸鱼所在的 14px 方框尺寸与位置都不动，所以行高和计时文本不会产生任何位移；`prefers-reduced-motion` 下停转并保留一帧静止画面。背景始终被裁到 border-box，因此用 `background-size: contain` 保证整朵花都在方框内——溢出会把花瓣切掉。

## 素材

全部素材离线打包在本插件内，不联网、不依赖活动页：
- `assets/spine/levels_spine_a/`：输入框右侧挂件用的 Spine（`.json` + `.atlas` + 贴图），取自活动页前端包里内联的数据与图片。同目录下的 `levels_spine_b` / `levels_spine_c` 仍随包保留（历史素材），不再加载。
- `assets/hua/levels_hua_a.png`：运行中小黄花的贴图，从活动页 `images/levels_hua.png` 图集里裁出。Atlas 里写的是 `bounds:0,0,78,82  rotate:90`，但 Spine 对 `rotate:90` 的区间按转置存放（包内实占 82×78），因此按 82×78 裁切后再转回来，才能拿到完整花形；接着把原画外圈的米白贴纸描边（`255,249,228`）从边缘 flood fill 抹掉（只保留深棕内描边与花瓣本体），最后修剪透明留白得到 74×77。它不以文件形式加载，而是由 `build-client.mjs` 内联成 data URI 写进样式表，因此首次绘制就是花，不需要挂载后再拉一次图。
- 浏览器端渲染使用 Esoteric Software 官方 Spine WebCanvas 运行时（v4.2.120），已内联进 `client.js`，遵循 Spine Runtimes License。

## 局限

- 立绘按 180×240 CSS 像素渲染，用骨骼文件中声明的 setup bounds 自动取景；不会随窗口缩放变大变小。
- 只加载「柔光之影」一位角色：`assets/spine/levels_spine_a/` 的素材约 1.8 MB，解码后贴图约数 MB。整页只有一个 180×240 的 canvas，没有常驻的全屏动画。
- 立绘使用 Canvas 2D 绘制；浏览器把标签页置于后台时 `requestAnimationFrame` 会暂停，动画会停在最后一帧（切回前台后继续）。
- 花朵的动画靠 CSS keyframes 驱动，与 Chat 自己那种由图片自带的动画时钟不同；因此它和其他 CSS 动画一样，后台标签页会被浏览器节流，但不会因为重挂而从头开始。
- 花朵用 `:has(> svg)` 定位 Chat 的图标方框，这是一种结构性选择器而非公开插槽；Chat 改了内部结构就会失配（表现为退回鲸鱼，不会报错）。
